## Часть A. Порождающие паттерны

### 1. Фабричный метод

Создание импортёра по типу источника.

### 2. Абстрактная фабрика

Два семейства согласованных компонентов:

| Фабрика | Вывод | Хранилище | Формат |
|---|---|---|---|
| `DevelopmentFactory` | консоль | in-memory | подробный |
| `ProductionFactory` | файл | БД | компактный |

**Требование:** компоненты одного семейства обязаны быть совместимы,
а смешать их не должно получиться. Если ваши три метода `Create*` возвращают
объекты, между которыми нет никакой связи, — это не Абстрактная фабрика,
а три независимых фабричных метода.

### 3. Строитель

Сборка конвейера обработки из конфигурации. Реализуйте **оба** варианта:

Классический, с директором:

```csharp
var director = new PipelineDirector(new StandardPipelineBuilder());
var pipeline = director.BuildDefault();
```

Fluent:

```csharp
var pipeline = new PipelineBuilder()
    .FromFile("app.log")
    .FilterBySeverity(Severity.Warning)
    .WriteTo(new ConsoleSink())
    .Build();
```

Строитель должен бросать понятную ошибку, если пропущен обязательный шаг.

### 4. Прототип

Шаблоны конфигураций: базовый профиль клонируется и донастраивается.

**Обязательно покажите разницу поверхностного и глубокого копирования на тесте:**
у клона и оригинала общий вложенный объект, мутация клона портит оригинал.
Затем — правильная версия с глубоким копированием, где этого не происходит.

## Часть B. Структурные паттерны

### 5. Адаптер

Подключите минимум два «внешних» приёмника с несовместимыми интерфейсами
к общему `ILogSink`:

* один с сигнатурой в стиле SQL: `Save(DateTime date, int severity, string message)`;
* другой принимает документ: `Push(JsonDocument doc)`.

Реализуйте **оба вида** адаптера — объекта (композиция) и класса (наследование).
В отчёте сравните: что удобнее в C# и почему.

### 6. Декоратор

Обвесьте любой приёмник тремя возможностями:

* замер времени записи;
* повтор при ошибке;
* буферизация.

**Требование:** декораторы складываются в любом порядке, и порядок виден
в поведении. Покажите на тесте два варианта сборки, дающих разный результат.

Декоратор с состоянием (буфер) обязан уметь освобождаться — иначе последняя,
неполная порция записей потеряется.

### 7. Заместитель

* **виртуальный** — соединение с БД открывается при первой записи, а не при старте;
* **кэширующий** — для чтения справочника.

Ленивость докажите тестом: до первого обращения соединение не открыто.

### 8. Компоновщик

Составные правила фильтрации: `И`, `ИЛИ`, `НЕ` над простыми предикатами.
Клиент работает с простым и составным правилом одинаково.

```csharp
var rule = new And(
    new SeverityAtLeast(Severity.Warning),
    new Not(new MessageContains("healthcheck")));
```

### 9. Фасад

Одна точка входа `LogHub.Run(config)`, за которой прячется вся сборка конвейера.

**Проверка:** программа-клиент должна занимать не больше пяти строк
и не содержать ни одного `using` внутренних пространств имён вашего проекта.

## Типичные ошибки

### 1. Абстрактная фабрика без семейств

Три метода `Create*`, между продуктами которых нет связи. Смысл паттерна —
в согласованности набора: если фабрика отдала консольный вывод, она обязана
отдать и совместимый с ним формат.

Проверьте себя: можно ли в вашем коде взять вывод из одной фабрики,
а формат из другой? Если да и это не ломается — семейства нет.

### 2. Декоратор и Заместитель не различаются

Код у них похож до неразличимости: оба реализуют интерфейс, оба хранят
ссылку на объект, оба делегируют вызов. Разница в намерении:

| | Декоратор | Заместитель |
|---|---|---|
| Зачем | добавить поведение | контролировать доступ |
| Сколько | несколько, стопкой | обычно один |
| Всегда ли вызывает обёрнутое | **да** | **нет** |
| Откуда берёт объект | получает готовым | часто создаёт сам |

Проверочный вопрос: **может ли ваша обёртка не вызвать то, что она обернула?**
Если может — это Заместитель.

В отчёте это различие нужно проговорить явно на примере вашего кода.
