# Чеклист перед сдачей

Пройдите перед тем, как открывать Pull Request. Половина возвратов
на доработку — из-за пунктов этого списка, а не из-за содержания работы.

---

## Сборка и тесты

- [ ] `dotnet build` проходит **без предупреждений**
- [ ] `dotnet test` — все тесты зелёные
- [ ] Отключённые тесты (`[Ignore]`) снабжены объяснением в скобках
- [ ] Нигде нет `#pragma warning disable` — предупреждения исправлены, а не заглушены
- [ ] CI на GitHub зелёный

Проверить предупреждения явно:

```bash
dotnet build --no-incremental -warnaserror
```

---

## Тесты по существу

- [ ] Минимум из задания выполнен
- [ ] Ни один тест не обращается к диску, сети или базе
- [ ] Нет `Thread.Sleep` в тестах
- [ ] Тесты проходят при запуске поодиночке и в любом порядке
- [ ] Имена тестов говорят, что проверяется, а не `Test1`, `Test2`

Проверить независимость от порядка:

```bash
dotnet test --filter "FullyQualifiedName~ИмяОдногоТеста"
```

---

## Git

- [ ] Работа в ветке `feature/лр-N`, не в `main` и не в `develop`
- [ ] Pull Request открыт **в вашем репозитории**: `feature/лр-N` → `develop`
      (в репозиторий преподавателя ничего не отправляется)
- [ ] Преподаватель имеет доступ: репозиторий публичный либо он добавлен
      в Collaborators
- [ ] В `main` нет прямых коммитов
- [ ] Коммиты осмысленные: не «фикс», «фикс2», «ещё фикс»
- [ ] В репозиторий не попали `bin/`, `obj/`, `.vs/`, `.idea/`
- [ ] В описании PR написано, что сделано

Проверить, что лишнее не закоммичено:

```bash
git ls-files | grep -E "^(.*/)?(bin|obj)/" && echo "ЕСТЬ ЛИШНЕЕ" || echo "чисто"
```

## Отчёт

- [ ] Файл `docs/ЛР{N}.md` существует
- [ ] Заполнены все разделы [шаблона](Шаблон_отчёта.md)
- [ ] **Есть раздел «Что не получилось»** — без него отчёт возвращается
- [ ] Указаны фамилия, группа и номер варианта
- [ ] В таблице паттернов колонка «почему» объясняет выбор,
      а не пересказывает определение
- [ ] Заимствования помечены ссылкой на источник

---

## Диаграммы

- [ ] Все диаграммы на PlantUML, исходником в репозитории
- [ ] Скриншотов из редакторов нет
- [ ] Диаграмма соответствует коду: классы, которые на ней нарисованы,
      действительно есть, и наоборот
- [ ] Диаграмма читается: не двадцать классов в одной куче

Проверить, что PlantUML валидный, можно на
<https://www.plantuml.com/plantuml/uml/> — вставьте исходник.

---

## Код

- [ ] Никаких `Console.ReadLine()` — они вешают CI и автопроверку
- [ ] Никаких закомментированных кусков «на всякий случай»
- [ ] Нет файлов `Class1.cs`, `Program2.cs`, `NewFolder/`
- [ ] Кодировка всех файлов — UTF-8
- [ ] Код из папки `_AntiPatterns` учебного репозитория не скопирован

## Специфичные проверки по работам

### ЛР 1

- [ ] Добавили новый приёмник → `git diff --name-only` показывает **только новые файлы**
- [ ] Поведение совпадает с исходным `god-object` на одном входном файле
- [ ] Нет интерфейсов с единственной реализацией, которую никто не подменяет

### ЛР 2

- [ ] `new` для сервисов встречается только в композиционном корне
- [ ] Обращение к `IServiceProvider` — ровно одно, в точке входа
- [ ] Есть тест, показывающий зависимость классического синглтона от порядка выполнения

### ЛР 3

- [ ] Два вложенных `foreach` по одному графу работают корректно
- [ ] Обход не зацикливается на графе с циклом
- [ ] Шаблонный метод невиртуальный, шаги `protected`

### ЛР 4

- [ ] В посетителях нет `is` и `switch` по типу записи
- [ ] `Accept` переопределён в каждом конкретном классе, а не вынесен в базовый
- [ ] Отписка наблюдателя показана тестом

### ЛР 5

- [ ] Компоненты разных семейств абстрактной фабрики нельзя смешать
- [ ] Декораторы собираются в двух разных порядках и дают разный результат
- [ ] Заместитель не открывает соединение до первого обращения — доказано тестом
- [ ] Программа-клиент через фасад ≤ 5 строк, без `using` внутренних неймспейсов
