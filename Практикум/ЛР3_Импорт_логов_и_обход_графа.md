## Часть A. Стратегия и Шаблонный метод

### 1. Три источника логов

Реализуйте импорт минимум из трёх источников. Один из них — формат вашего варианта
(см. [таблицу вариантов](README.md#ваш-вариант)), остальные два на выбор:
текстовый файл, CSV, JSON, syslog, in-memory.

Источник in-memory обязателен — без него не написать тесты, не трогающие диск.

### 2. Выбор источника — Стратегией

`ILogImporter` подставляется в `LogProcessor` в рантайме. Смена источника
не должна требовать ни `if`, ни пересборки.

### 3. Общий алгоритм — Шаблонным методом

Вынесите скелет чтения в базовый класс: открыть → прочитать → разобрать →
закрыть → освободить.

* шаги «прочитать» и «разобрать» — абстрактные;
* шаг «валидация» — хук с реализацией по умолчанию;
* сам шаблонный метод — **невиртуальный**.

### 4. Показать работу хука

Один из импортёров переопределяет валидацию, остальные — нет
и о её существовании не знают.

## Часть B. Итератор и обход графа

### Вход

Граф зависимостей сервисов LogHub: узел — сервис, ребро — «зависит от».
Каркас в [Репозиторий: `Implementation/Graphs/`](../DesignPatterns/Implementation/Graphs/).

### 5. Два обхода

Реализуйте `IEnumerable<Node>` с двумя независимыми обходами:
в глубину (DFS) и в ширину (BFS).

### 6. Вложенные циклы обязаны работать

```csharp
foreach (var service in graph.DepthFirst(root))
{
    foreach (var dependency in graph.BreadthFirst(service))   // должно работать
    {
        Console.WriteLine($"{service} → {dependency}");
    }
}
```

Это требование исключает решение «коллекция сама себе итератор».
Антипример — [Репозиторий: `_AntiPatterns/Enumerator/MyCollection.cs`](../DesignPatterns/Implementation/_AntiPatterns/Enumerator/MyCollection.cs),
запустить: `dotnet run --project Implementation -- anti-enumerator`.

### 7. Циклы в графе

Граф зависимостей может содержать цикл. Обход не должен зацикливаться.
Найдите циклическую зависимость и выведите её путь.

### 8. Две реализации итератора

Сделайте обход двумя способами:

* вручную — класс с `MoveNext()`, `Current`, `Reset()`, `Dispose()`;
* через `yield return`.

В отчёте сравните: во что компилятор разворачивает `yield return`
и почему получается то же самое. Подсказка: откройте результат в декомпиляторе
(ILSpy, dotPeek или `Rider → Decompile`) и найдите вложенный класс
с полем состояния.

## Типичная ошибка

**Сделать Стратегию наследованием, а Шаблонный метод — делегатом.**

Тогда оба паттерна схлопываются в один и смысл работы теряется.

Держите в голове разницу: Стратегия заменяет **весь алгоритм** подстановкой
объекта в рантайме; Шаблонный метод меняет **отдельный шаг** через наследование
на этапе компиляции. Если у вас наследники, переопределяющие все шаги
без исключения, — это Стратегия, записанная наследованием, и переиспользования
в ней нет.
