# Практикум по разделу «Паттерны программирования»

Пять лабораторных работ. Все пять строят один проект — **LogHub**, систему сбора
и обработки логов. Каждая работа добавляет к нему новый слой.

---

## Зачем один проект вместо пяти отдельных

Паттерн, реализованный в вакууме, не запоминается: получается набор классов
`ConcreteProductA`, которые никуда не ведут. Когда система одна и растёт,
вы сами упираетесь в проблему, которую паттерн решает, — и решение перестаёт
быть формальным.

К пятой работе у вас будет рабочий проект, который не стыдно показать
на собеседовании.

## Ваш вариант

Номер варианта — **номер в списке группы**. Если в группе больше 20 человек,
вариант определяется как `(номер в списке − 1) mod 20 + 1`.

Вариант задаёт формат входных логов и набор приёмников. **Во всех пяти работах
вариант один и тот же** — это и есть сквозной проект.

| № | Формат источника | Приёмники (мин. 2) | Особое требование |
|---|---|---|---|
| 1 | Plain text, `[дата] УРОВЕНЬ сообщение` | Консоль, файл | Ротация файлов по размеру |
| 2 | CSV с заголовком | Консоль, SQLite | Разделитель задаётся конфигурацией |
| 3 | JSON Lines | Файл, in-memory | Вложенные поля |
| 4 | Syslog RFC 5424 | Консоль, файл | Разбор приоритета |
| 5 | W3C Extended Log (веб-сервер) | SQLite, консоль | Динамический набор колонок |
| 6 | XML | Файл, консоль | Валидация по схеме |
| 7 | Apache Common Log | in-memory, файл | Разбор User-Agent |
| 8 | Ключ-значение (`k=v k=v`) | Консоль, SQLite | Произвольный набор ключей |
| 9 | Многострочные записи со stack trace | Файл, консоль | Склейка строк одной записи |

| 15 | Логи Docker (`docker logs`) | in-memory, файл | Разделение stdout/stderr |
| 16 | Journald export | Консоль, SQLite | Разбор unit и приоритета |

обязательно с «плохими» строками, которые не разбираются.

## Куда и как сдавать

### Коротко

Вы работаете **в своём репозитории**. В репозиторий преподавателя ничего
не отправляется никогда.

```
репозиторий преподавателя  ──fork──►  ваш репозиторий  ──►  вы работаете здесь
   (только читаете,                      (пишете,
    забираете обновления)                 открываете PR сам себе)
```

Сдача работы — **ссылка на Pull Request в вашем репозитории**, отправленная
преподавателю тем способом, который принят в вашей группе (система обучения,
почта, чат курса).

### Один раз в начале семестра

**1. Форк.** На странице учебного репозитория нажмите **Fork**.
Получится копия у вас в аккаунте: `github.com/<ваш-логин>/<репозиторий>`.

**2. Клон и remote-ы.**

```bash
git clone https://github.com/<ваш-логин>/<репозиторий>.git
cd <репозиторий>

# origin  — ваш форк, сюда вы пушите
# upstream — репозиторий преподавателя, отсюда забираете обновления
git remote add upstream https://github.com/clgray/Lecture_Examples.git
git remote -v
```

**3. Ветки.**

```bash
git checkout -b develop
git push -u origin develop
```

На GitHub: **Settings → Branches → Add rule** — защитите `main`
от прямого push. Сделайте `develop` веткой по умолчанию
(**Settings → General → Default branch**), чтобы Pull Request'ы
открывались в неё автоматически.

**4. Доступ преподавателю.** Репозиторий может быть публичным —
тогда достаточно прислать ссылку. Если делаете приватным,
добавьте преподавателя: **Settings → Collaborators → Add people**.

### На каждую работу

```bash
git checkout develop
git pull                          # подтянуть свои же изменения
git checkout -b feature/лр-3      # ветка под работу

# ... код, коммиты ...

git push -u origin feature/лр-3
```

Дальше на GitHub: **Compare & pull request** → база `develop`,
источник `feature/лр-3` → **Create pull request**.

В описании PR коротко: что сделано, какие паттерны применены,
что не получилось. Ссылку на PR отправляете преподавателю.

**PR не сливайте до проверки.** Замечания приходят комментариями
к строкам кода — исправляете, пушите в ту же ветку, PR обновляется сам.
После «принято» сливаете в `develop` сами.

### Перед защитой

Когда все пять работ приняты:

```bash
git checkout main
git merge develop
git tag -a v1.0.0 -m "LogHub: итоговая версия"
git push origin main --tags
```

### Если преподаватель обновил материалы

Задания и примеры кода в течение семестра правятся. Забрать обновления:

```bash
git fetch upstream
git checkout develop
git merge upstream/main
```

Ваш код при этом не пострадает: вы правите `LogHub/`, а обновления
приходят в `Git/` и `DesignPatterns/`.

## Правила сдачи

1. Работа сдаётся **Pull Request'ом внутри вашего репозитория**:
   `feature/лр-N` → `develop`. Коммиты прямо в `main` не принимаются.
2. **Зелёный CI.** Не собирается — не проверяется, работа возвращается сразу.
3. **Отчёт** `docs/ЛР{N}.md` по шаблону (см. «Шаблон отчёта»).
4. **Тесты** — минимум указан в задании каждой работы.
5. **Диаграммы** — только PlantUML в репозитории. Скриншоты из редакторов
   не принимаются: их нельзя ни проверить, ни поправить.
   Синтаксис и типичные ошибки — в учебнике, глава «Диаграммы на PlantUML».
6. **Код без предупреждений компилятора.** Отключать предупреждения
   директивами `#pragma warning disable` нельзя — правьте причину.

Перед отправкой пройдите чеклист самопроверки.

## Оценка

Каждая работа оценивается по шкале 2–5, критерии — в задании.
Итог складывается из весов работ и умножается на коэффициент защиты.

| Защита | Коэффициент |
|---|---|
| Свободно объясняете свои решения и их альтернативы | 1,0 |
| Отвечаете с наводящими вопросами | 0,85 |
| Плаваете в базовых понятиях | 0,7 |

Работа, сданная после срока, — минус балл за каждую неделю,
но не ниже 3 при выполненном задании.

### Защита проекта

На последнем занятии:

* демонстрация работающего LogHub на своих данных, 7 минут;
* полная диаграмма классов;
* три вопроса по любому паттерну из курса;
* один вопрос обязательный: **«где в вашем проекте паттерн лишний
  и что стало бы проще без него?»**

Последний вопрос — не формальность. За курс вырабатывается привычка
ставить паттерн потому, что его проходили. Умение показать, где он не нужен,
и есть результат раздела.

## Про заимствование

**Заимствованный код помечается ссылкой на источник в комментарии.**
Это нормальная практика, за неё не снижают балл.

Незадекларированное заимствование — 2 балла независимо от качества работы.
Это касается и кода из интернета, и кода однокурсника, и кода,
сгенерированного языковой моделью.

Отдельно: **код из папки `_AntiPatterns` учебного репозитория копировать нельзя.**
Он там специально неправильный и помечен комментариями `// АНТИПРИМЕР:`.
